# Development Instructions for lmslogger

## Overview
lmslogger is a Python daemon that connects to a Lyrion Music Server (LMS) on port 9090, sends commands, and receives/decodes status information. It runs as a systemd service or CLI tool.

## Key Development Guidelines

### Code Quality & Standards
See [docs/constitution.md](docs/constitution.md) for detailed principles:
- PEP 8 compliance
- Strong typing with type hints validated by mypy
- All data structures must be statically and dynamically type-checked
- Defensive coding practices
- Comprehensive docstrings and comments
- DRY and SOLID principles

### Security Requirements
See [docs/constitution.md](docs/constitution.md#security):
- Secure coding practices to prevent vulnerabilities
- Input validation
- Secure communication protocols
- Least privilege access
- Regular dependency updates
- No sensitive data in plain text

### Testing Standards
See [docs/constitution.md](docs/constitution.md#testing):
- Test-driven development (TDD): write tests before implementing
- Maintain ≥85% test coverage
- Unit tests for components
- Integration tests for system interactions
- Automated CI/CD testing

### Software Development Life Cycle
See [docs/SDLC.md](docs/SDLC.md) for the full SDLC process:
1. Planning Phase: define requirements
2. Design Phase: architecture and components
3. Implementation Phase: write code with type hints and TDD
4. Testing Phase: unit, integration, type checking, manual testing
5. Deployment Phase: package and deploy
6. Maintenance Phase: monitoring and updates

## Project Structure
- `src/lmslogger/` — main package
  - `daemon.py` — entry point and CLI logic
  - `config.py` — configuration management using pydantic
  - `network.py` — socket communication handler
- `tests/` — unit and integration tests
- `pyproject.toml` — Python package metadata
- `lmslogger.spec` — RPM package specification
- `lmslogger.service.template` — systemd service template

## Running Tests
```bash
pytest
mypy src/
```

## Before Committing
- All tests pass
- Type checking passes (`mypy src/`)
- No test is broken
- Commit message focuses on a single change

## CLI Flags
The daemon supports CLI configuration flags that override environment variables and `.env` file values:
- `--env-file` — path to .env file
- `--host` — LMS host
- `--port` — LMS port
- `--command` — command to send to LMS
- `--poll-interval` — seconds between polls
- `--alive-messages` / `--no-alive-messages` — control heartbeat output
